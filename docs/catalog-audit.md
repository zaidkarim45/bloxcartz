# Catalog Migration Audit

Source: live crawl of `https://bloxcart.com/` on 2026-08-28/29. Method, findings, and licensing notes for the BloxCart → BloxxCart product/asset migration.

## Methodology

1. **Structural crawl** (`scripts/crawl_catalog.py`): plain `curl` against each confirmed category URL (e.g. `/store/murder-mystery-2/products/guns/`). bloxcart.com's Next.js app **server-renders** product name, product URL, full-resolution source image URL, and the rarity accent-bar color directly into the initial HTML — confirmed by inspecting raw response bytes before any JavaScript runs. No browser automation was needed for this pass, which is why 296 products across 18 category pages (23 including pagination) could be crawled in seconds with zero errors.
2. **Pagination**: category listings server-render in batches of 24; anything over 24 items (Steal a Brainrot's Brainrots: 106 items over 5 pages; Blox Fruits' Permanent Fruits: 40 items over 2 pages) required following `?page=N`. Verified no items were skipped or duplicated by cross-checking final counts against the filter-sidebar's own published counts (Phase 0 findings) — every category matched exactly.
3. **Price / compare-at price / stock status**: confirmed NOT server-rendered (the raw HTML shows a loading skeleton in place of the price). This data only exists after client-side JavaScript hydration, so it was collected with a real headless browser, one page load per category (23 total), reading the hydrated DOM directly. Merged with the structural data by matching each product's URL path — zero mismatches, zero missing entries.
4. **Rarity names**: the accent-bar *color* is server-rendered per product, but the *name* ("Godly", "secret", "mythic", etc.) only appears in the filter sidebar, not on individual product cards. Each game's sidebar was inspected once to build a color→name legend (`scripts/resolve_rarity.py`). Several games reuse an identical color for two different rarity tiers (see "Known limitations" below) — those cases are left unresolved rather than guessed.
5. **Images**: every `source_image_url` is the actual Shopify CDN file the live site itself displays (`cdn.shopify.com/s/files/1/0815/2068/9482/...`) — the *original*, not the Next.js-resized copy the browser normally loads. Files came back as 1024–3000px PNGs/WebPs with real alpha transparency already baked in.
6. **Game artwork**: each game's card thumbnail + small icon were found via `<link rel=preload>` tags on the homepage, hosted on `media.bloxcart.com/payload-media/` — a separate Payload CMS media bucket from the Shopify-hosted product catalog. Downloaded directly, 18 files (9 games × 2 asset types), zero failures.

## Critical finding: this is the merchant's own existing catalog, not third-party content

The images being migrated are already hosted on **the requester's own Shopify store** (confirmed Shopify Plus, per Phase 0's `/guarantee` page finding) and already displayed commercially at bloxcart.com. This migration moves them to a second storefront the same merchant is building on the same underlying commerce platform — not copying a stranger's content.

That said, the underlying *artwork* (in-game item renders for Murder Mystery 2, Blox Fruits, etc.) depicts third-party Roblox game IP that BloxCart does not own — its own footer explicitly disclaims any affiliation with Roblox Corporation or the respective game developers, and states these are used "for identification purposes only." This is the same legal posture as any resale marketplace showing photos of the goods it resells (e.g. a sneaker resale site using manufacturer product photos) — a defensible, common commercial practice, but not something I can certify as risk-free. **This is a business/legal judgment call for the merchant, not a technical one** — flagging per the explicit instruction not to silently assume reuse rights are clear. No image in this migration was substituted with AI-generated artwork; every file is the genuine asset the live site itself serves.

## Data model decisions

- **Bundles are single-SKU products**, not grouped collections — confirmed by inspecting MM2's one bundle ("Ocean Bundle"): it's a normal single product card/PDP like any other item, not a curated multi-product group. Answers spec open question #3.
- **Rarity is modeled as a free-text tag** (`rarity:{name}`), not a fixed enum — confirmed necessary: rarity vocabularies differ per game (Godly/Ancient/Unique for MM2 vs. Common/secret/og for Steal a Brainrot vs. a 5-tier system for Blox Fruits) and casing is inconsistent even within one game.
- **Category is modeled as a tag** (`category:{slug}`), one per product, derived directly from which category URL the product was crawled under — "All items" and "Best Sellers" were intentionally NOT crawled as categories since they're cross-cutting views of the same underlying catalog, not real subdivisions; crawling them would have produced duplicate product entries.
- **Adopt Me has no internal catalog** — confirmed (again) as an external-only NeonPets affiliate link. It's included in `assets/catalog/games/` (real card artwork exists) but contributes zero rows to `data/catalog.json`.

## Known limitations (do not treat catalog.json as 100% complete)

- **Product descriptions**: not captured at scale. Real description copy was only confirmed for one product (Gingerscope Gun, from Phase 0's manual PDP inspection). `Body (HTML)` is left blank for all 296 rows in `shopify-products.csv` rather than inventing generic copy. Capturing real descriptions for all 296 would require visiting every product detail page individually (not done in this pass — flagged as follow-up work, see `docs/catalog-qc.md`).
- **Rarity name ambiguity**: 180 of 296 products (61%) belong to a rarity tier whose accent color is shared by more than one rarity name within that game (e.g. Steal a Brainrot's "secret" and "og" are both `#C0C0C0`). For these, `catalog.json` sets `rarity_name: null, rarity_ambiguous: true` rather than guessing, and the generated CSV omits the `rarity:` tag entirely for them. Only 116 products (39%) got an unambiguous rarity tag. Resolving the rest would need either visiting each product's detail page (rarity name is likely stated there, as confirmed for Gingerscope Gun's "Ancient" badge in Phase 0) or asking the merchant.
- **Stock quantity**: only a binary in-stock/out-of-stock signal is publicly visible on the site — no real quantity. The CSV uses a placeholder `10` for in-stock items and `0` for out-of-stock, which is enough to make availability display correctly but is **not real inventory data**.
- **Image Src in the CSV points at the original bloxcart.com source URL**, not the locally processed/normalized copy in `assets/catalog/processed/` — see `docs/catalog-qc.md` for why, and the plan to swap it once there's a way to get local files onto Shopify's CDN (Admin API access or manual bulk upload).
